# SDK 0.2 validation

Validated against internal dev EKS on 28 September 2026, after the deployment's
raw HTTP/WebSocket pipeline smoke passed. BFF source revision `e9fc257` includes
pagination PR 149 plus fixes for M2M discovery and rejected WebSocket upgrades.

- 51 local tests passed; Ruff reported no errors. The 0.2.0 wheel built.
- Three live cases passed through the public ALB using an approved 12-second
  mono PCM16LE 16 kHz fixture: omitted track selections, explicit Whisper tracks
  with partial results disabled, and realtime-only with refinement/final disabled.
- Verified M2M discovery, rename, per-track completion, saved refinement/final
  identity, filtered history, pagination counts and WAV range download.
- Each test disabled tenant workflow/webhook defaults for its own session and
  deleted that session afterward. Tenant defaults and credentials were unchanged.

The first live attempt exposed the BFF's bounded ingress queue dropping frames
when the SDK burst-sent a file. The sender now paces audio at its declared sample
rate. Completion checks rejected the truncated refinement instead of reporting
success. A pacing regression test and the repeated live cases passed afterward.
The interrupted diagnostic session was also removed.

Completion tests cover multiple selected tracks and refinement tails, continuous
events that never complete, sender/handshake/provider/callback failures and
cancellation. Live validation used only the deployed Faster Whisper/WhisperX
tracks; simultaneous alternate providers were tested with fixtures, not deployed.

## Compatibility and security

This release requires the track API and pagination counts. It preserves the list
return type and omitted-track behavior, but removes flat realtime tuning options
and requires source tracks on transcript workflows. Keep the existing consumer
pinned to `5b86461` until its coordinated upgrade; there is no protocol fallback.

The SDK continues to verify TLS and use existing client credentials. No new
credentials, destinations or tenant configuration are provisioned. Test logs
exclude tokens and transcript content. EKS remains internal dev, subject to the
network and dependency risks recorded in Nanodeploy; this SDK validation does
not qualify the deployment for public access.
